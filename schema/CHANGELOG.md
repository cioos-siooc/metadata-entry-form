# Changelog

All notable changes to the CIOOS metadata record schema.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the
versioning policy is in [README.md §4](./README.md).

Reminder on what each bump means here:

- **PATCH** — text, examples, docs only
- **MINOR** — new optional property, widened enum, relaxed constraint, or a
  tightening of `record.submission.schema.json` alone
- **MAJOR** — new required structural property, property removed or renamed,
  enum narrowed, type narrowed. Bumps the `$id` path; the previous major stays
  published and frozen.

## [1.0.0] — unreleased

First version. Describes the record as it exists today; no behaviour changes to
the form.

### Added

- `record.schema.json` — structural description of a record (49 properties,
  24 definitions), draft-07, generated from `src/schema/`.
- `record.submission.schema.json` — structural plus the requirements enforced by
  `recordIsValid()` in `src/utils/validate.js`.
- `record.en.schema.json` / `record.fr.schema.json` — monolingual variants for
  the docs generator.
- `i18n.json` — derived `{jsonPointer: {en, fr}}` label map.
- Optional `schemaVersion` property, stamped on new records by
  `getBlankRecord()`.
- `x-cioos-bbox-ordered`, `x-cioos-coordinate-ranges`, and
  `x-cioos-polygon-closed` for the three rules JSON Schema cannot express.
- Bilingual browsable documentation under `docs/build/`, generated by
  `npm run schema:docs` and published at `/schema/` alongside the schema files.
- `docs/conditional-requirements.{en,fr}.md` — the cross-field rules, written
  by hand because the generator renders conditionals poorly.

### Notes

- Types match what is in the database today, not what would be tidier —
  bounding box edges and vertical extents are strings, dates are full ISO-8601
  with milliseconds. See README §5.
- `""` is the universal "unset" value and is structurally valid everywhere,
  including for fields carrying `format: email` / `format: uri`.
- Bbox ordering, coordinate ranges, and polygon closure are validity rules and
  live only in the submission schema. A published legacy record with a reversed
  box is still structurally a record.
- Three pre-existing inconsistencies in `validate.js` are documented rather
  than silently resolved — see README §10. One of them (the lineage statement
  requirement never firing) is a live divergence pinned in
  `src/schema/__tests__/agreement.test.js`.
